# 统一按钮交互设计方案（最终版）

> 基于 20 名测试者反馈 + 实地老年人施测观察 + 双源文献调研，2026-04-07  
> 目标设备：Surface Pro 11 横屏（CSS 1440×960，1mm ≈ 5.24px）  
> 目标人群：60-85岁老年人，部分从未使用过触屏

---

## 一、实地施测发现的核心问题

### 问题 1：用力按压 → 手指漂移 → 判定无效

老人担心按不到所以按得很用力，用力后手指微移超出漂移阈值（当前30px≈5.7mm），被判定为无效触摸。

- **文献**：老年人触屏按压力度是年轻人的2-3倍，平均漂移8-12mm（Chung 2021, PMC7924826; Findlater 2013）
- **当前阈值**：`MAX_DRIFT_PX = 30`（5.7mm），**不够**

### 问题 2：一手搭屏 + 另一手点击 → 被阻止

左右判断时老人无法悬浮双手，一只手搭在屏幕上，另一只手去点，结果第二个触点被代码吞掉。

- **根因**：`touch-hardening.js:64` 的 `if (e.touches.length > 1) { e.preventDefault(); e.stopImmediatePropagation(); }` 直接阻止了第二个触点
- **这是老人"按不到"的最直接代码级原因**

### 问题 3：按下后微移 → 判定无效

老人按下去后手指不自觉移动一点点，触发 touchmove → 超出 drift → 取消点击。

### 问题 4：按钮位置和大小不好

屏幕大，中间/两边都不好按，按钮偏小。

### 问题 5：手指干燥 → 电容屏无响应（硬件级）

老年人皮肤干燥导电性差，40岁以上超过一半有此问题（Mayo Clinic）。电容屏检测不到触摸，**软件无法解决**。

## 三、老年人触控生理特点（文献综合）

| 维度 | 退化表现 | 对触控影响 | 来源 |
|------|---------|----------|------|
| 视觉 | 视力下降、对比度敏感度降低 | 难以识别小按钮 | Wilson 2021 |
| 运动控制 | 精细动作下降、手抖 | 难以精准点击，容易偏移 | Chung 2021 |
| 触觉 | 皮肤触觉敏感度下降、干燥 | 需要更强确认反馈；干手电容屏无响应 | Mayo Clinic |
| 认知 | 反应时间延长 | 需要更充足响应时间 | PMC7924826 |

**关键数据**：
- 老年人触点偏移平均 8-12mm（Findlater 2013）
- 操作速度慢 50-100%（Chung 2021）
- 按压力度是年轻人 2-3 倍
- 40岁以上超半数有皮肤干燥问题

## 五、按钮位置规范

### 文献结论

| 来源 | 结论 |
|------|------|
| Yeh (2025) | 上方和右侧按钮反应时间最短、错误率最低 |
| PMC7330495 | 老年人在按钮位于屏幕上半部分时表现更好 |
| Smashing Magazine | **平板与手机不同**：平板双手持握时拇指触达区在两侧边缘，底部正中央是"难以触达区" |

### 具体方案

| 场景 | 当前 | 建议 | 理由 |
|------|------|------|------|
| 单按钮（SART） | 底部居中 | **保持**（老人用食指点，非拇指持握） | 改位置影响范式标准化 |
| 双按钮（Flanker左/右） | 底部左右 | **缩短间距**至屏幕60%宽度范围内 | 当前太分散 |
| 双按钮（VSTMB相同/不同） | 底部左右 | 保持 | 已经在自然位置 |
| 三按钮（Clock） | 底部横排 | 保持 | 功能按钮不需要高频操作 |
| 导航按钮（继续/开始） | 底部居中 | 保持 | 低频操作，不影响 |

## 六、触控反馈设计

### 双阶段反馈（统一所有范式）

**阶段1 — 按下（pointerdown，<60ms响应）**：
```css
.elderly-pressing {
  opacity: 0.80 !important;
  transform: scale(0.92) !important;
  transition: opacity 0.06s, transform 0.06s !important;
}
```

**阶段2 — 松开确认（pointerup，持续300ms）**：
```css
.elderly-confirmed {
  box-shadow: 0 0 0 4px rgba(255,255,255,0.7),
              0 0 12px rgba(255,255,255,0.3) !important;
  transition: box-shadow 0.08s !important;
}
```

白色边框高亮，适配黑底（SART）和白底（其他范式）。

### 音效反馈（可选，默认关闭）

研究表明音效+视觉反馈组合效果显著优于纯视觉（Wilson 2021）。但考虑施测环境可能有多个被试同时进行，**默认关闭，由主试决定是否开启**。

| 事件 | 音效 | 频率 | 时长 |
|------|------|------|------|
| 按下 | 短促"咔嗒" | 1000-1500Hz | 50ms |
| 确认 | 清脆"叮" | 800-1200Hz | 100ms |

技术实现通过 Web Audio API，不依赖外部音频文件。

### 触觉反馈

```javascript
if (navigator.vibrate) navigator.vibrate(50);
```

Surface Pro 不支持vibrate API，此项仅作为手机/部分平板的增强。

## 七、touch-hardening.js 改动清单

### P0 紧急：多指触控策略改写 ✅ 已完成

**原问题**：第二个触点事件被直接阻止 → 一手搭屏另一手按不到  
**已改为**：删除 touchstart 级别的多指阻止（`touch-hardening.js:63-66`）。

### P0 紧急：全局 touch-action: none 缺口 ⚠️ 未修复

**问题**：左手搭在屏幕非按钮区域 + 右手按按钮 → 页面缩放 + 右手点击被吞掉。

**根因分析**：
```
touch-hardening.js 注入的 CSS:
  html, body → 只有 -webkit-touch-callout: none + overscroll-behavior: none
  按钮选择器 → 有 touch-action: none

缺口：html, body 没有 touch-action: none
  → 非按钮区域（黑色背景、刺激显示区）仍允许浏览器手势解释
  → 两指同时在屏幕上时，浏览器把它们理解为 pinch-to-zoom
  → 右手指的 pointerdown/pointerup 被消费为手势的一部分，不触发按钮逻辑
```

**因果链**：
```
老人左手搭屏（背景区，无 touch-action: none）
  ↓
右手按按钮
  ↓
浏览器：两个触点 → pinch-to-zoom 手势
  ↓
后果 1: 页面缩放（两指距离变化）
后果 2: 右手 tap 被吞掉 → "按不到"
```

**为什么 viewport meta 不够**：Chrome/Edge 从 2017 年起对 `user-scalable=no` 的遵守是可选的（出于无障碍合规），某些版本会忽略。`touch-action: none` 是 CSS 级硬性约束，浏览器必须遵守。

**修复**（`touch-hardening.js:86-89`）：
```diff
  'html, body {\n' +
  '  -webkit-touch-callout: none !important;\n' +
  '  overscroll-behavior: none !important;\n' +
+ '  touch-action: none !important;\n' +
  '}\n' +
```

一行即可。文档根级别禁止所有浏览器手势解释（pan/zoom/pinch），不管手指在哪个元素上。

### P0 紧急：漂移容忍增大 ✅ 已完成

```
MAX_DRIFT_PX: 30 → 50  （5.7mm → 9.5mm，覆盖老年人95%漂移量）
```

### P1：确认反馈加强

```
CONFIRM_FLASH_MS: 180 → 300
```

样式从绿色辉光改为白色边框高亮（见第六节）。

### P1：按下反馈统一

```
scale: 0.93 → 0.92
opacity: 0.82 → 0.80
```

使按下效果更明显。

## 九、干手问题解决方案（产品化）

### 不可行的方案

- ❌ 触控笔（需要额外设备，不适合百姓家产品化）
- ❌ 导电手指套（同上）
- ❌ 软件层面调整灵敏度（电容屏硬件限制）

### 产品化方案：触屏检测环节

在测试开始前自动检测触屏是否可用：

1. 首页显示一个**大色块**（占屏幕50%以上），提示"请点击这里开始"
2. 如果 **5秒内无触摸事件**，自动弹出提示：

> 🖐 检测到触屏可能无法识别您的手指  
> 请用湿纸巾擦一下手指，或洗一下手再试

3. 点击成功后正常进入测试

**技术实现**：监听 `pointerdown` 事件，超时后显示提示。不需要额外硬件。

### 施测SOP补充

施测手册中增加：
- 施测前准备物品清单增加"湿纸巾/保湿霜"
- 施测前检查步骤增加"确认被试手指能正常操作触屏"
- 如被试手干无法操作，先用湿纸巾擦手指等30秒
