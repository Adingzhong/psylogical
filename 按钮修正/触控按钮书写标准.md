# 触控按钮书写标准 v1.0

> 2026-04-09
> 适用范围：web-battery/ 下所有范式的响应按钮
> 核心文件：lib/touch-hardening.js

---

## 一、设计原则

1. **RT 在 pointerdown（手指触屏瞬间）记录** — 不等松开，不等 click
2. **第一次有效按压记 RT，后续只计数** — 响应锁定，防止重复点击污染数据
3. **所有按压都记录运动指标** — hold 时长、漂移距离、点击次数、输入类型
4. **一手搭屏另一手点必须能用** — 不阻止多指触控，用 touch-action: none 防缩放
5. **按下有即时反馈，松开有确认反馈** — 老人需要知道"按到了"
6. **鼠标走原生路径不拦截** — 开发调试不受影响

---

## 二、touch-hardening.js 提供的能力

### 2.1 全局防护（自动生效，范式无需任何代码）

| 防护 | 机制 | 解决的问题 |
|------|------|-----------|
| 长按右键菜单 | contextmenu preventDefault | 老人长按弹出系统菜单 |
| 双指缩放 | html,body touch-action: none | 一手搭屏+一手点 → 页面缩放 |
| 双击缩放 | touchend 300ms 间隔阻止 | 老人快速重复点击触发缩放 |
| Ctrl+滚轮缩放 | wheel 事件拦截 | 误触键盘 |
| hover 粘滞 | @media (hover:none) 清除 | 触屏设备 hover 状态不消失 |
| overscroll 弹性 | overscroll-behavior: none | 页面弹性滚动干扰 |

### 2.2 jsPsych 按钮自动包装（自动生效）

当 jsPsych 的 `html-button-response` 或 `image-button-response` 插件创建按钮时，MutationObserver 自动检测并包装。

**包装后的行为**：
- pointerdown → 记录 RT 起点 + 视觉反馈（.elderly-pressing）
- pointermove → 记录漂移数据
- pointerup → 验证漂移/时长 → 有效则触发 click → jsPsych 处理响应
- 仅拦截 touch/pen，鼠标走原生 click

**范式需要做的**：在 on_finish 中调用 `TouchHardening.correctRT(data)`。仅此一行。

### 2.3 自定义按钮包装（手动调用）

对于不用 jsPsych 标准按钮插件的范式（如 N-back 自建按钮、人际距离停止按钮）：

```javascript
TouchHardening.setupButton(buttonElement, function(e) {
    // 有效按压后的回调
}, {
    trackRT: true,        // 是否记录 RT（默认 true）
    debounce: true,       // 是否防抖 400ms（默认 true）
    confirmFlash: true,   // 是否确认闪烁（默认 true）
    mouseAlso: false      // 是否也拦截鼠标（默认 false）
});
```

### 2.4 RT 校正 + 运动指标输出

在 jsPsych trial 的 `on_finish` 中调用：

```javascript
on_finish: function(data) {
    TouchHardening.correctRT(data);
}
```

调用后 data 上会出现以下字段：

| 字段 | 类型 | 含义 | 来源 |
|------|------|------|------|
| `rt` | number | 校正后 RT（pointerdown 时刻，认知决策时间） | 覆盖 jsPsych 原始值 |
| `rt_original` | number | 原始 RT（click 时刻，含按压时长） | 新增 |
| `rt_hold` | number(ms) | 按压时长（pointerup - pointerdown） | 新增 |
| `drift_max` | number(px) | 按压期间离初始触点最大位移 | 新增 |
| `drift_path` | number(px) | 手指运动轨迹总长 | 新增 |
| `drift_end` | number(px) | 松手时离起点距离 | 新增 |
| `tap_count` | number | 本次试次内总点击次数（含第一次） | 新增 |
| `input_type` | string | 输入类型：'touch' / 'pen' / 'mouse' | 新增 |

**如果是鼠标操作**（开发调试），上述字段不会出现（correctRT 直接 return），jsPsych 原始数据不受影响。

## 三、各范式接入标准

### 类型 A：使用 jsPsych html-button-response 的范式

**适用**：Flanker、VSTMB 的探测试次、眼动的继续按钮

**接入方式**：什么都不用改，auto-wrap 自动生效。只需确保 on_finish 有 correctRT。

```javascript
// 范式 JS 中的 trial 定义
{
    type: jsPsychHtmlButtonResponse,
    stimulus: '...',
    choices: ['选项A', '选项B'],
    on_finish: function(data) {
        TouchHardening.correctRT(data);   // ← 这一行
        // ... 其他数据处理
    }
}
```

**检查清单**：
- [ ] on_finish 中有 `TouchHardening.correctRT(data)` 调用
- [ ] HTML 中 `<script src="../../lib/touch-hardening.js"></script>` 已引入
- [ ] 没有自定义的 :active CSS 与 .elderly-pressing 冲突（如有，删掉自定义的）

### 类型 B：自建 HTML 按钮的范式

**适用**：N-back（自建 3 按钮）、人际距离（停止按钮）、语音（录音按钮）

**接入方式**：手动调用 setupButton。

```javascript
var myBtn = document.getElementById('my-response-btn');

// 响应锁定：用闭包变量控制
var _responded = false;
var _tapCount = 0;
var _firstRT = null;

TouchHardening.setupButton(myBtn, function(e) {
    _tapCount++;
    
    if (!_responded) {
        // 第一次：记录 RT
        _responded = true;
        _firstRT = performance.now() - trialStartTime;
        // ... 处理响应逻辑
    }
    // 后续点击：只增加 tap_count，不记录新 RT
    // 按钮仍有视觉反馈（setupButton 自动处理）
});

// 试次结束时写入数据
function onTrialFinish(data) {
    data.rt = _firstRT;
    data.tap_count = _tapCount;
    TouchHardening.correctRT(data);  // 补充 drift 等字段
}

// 下一个试次开始时重置
function onNextTrial() {
    _responded = false;
    _tapCount = 0;
    _firstRT = null;
}
```

**检查清单**：
- [ ] 使用 setupButton() 而非自己写 addEventListener
- [ ] 实现了响应锁定（_responded 标志）
- [ ] 第一次记 RT，后续只计数
- [ ] 试次结束时调用 correctRT()
- [ ] 下一试次开始时重置状态

### 类型 C：SART（persistent 按钮，自己管理 pointerdown）

**SART 是特殊情况**。它的按钮跨试次持续存在（不被 jsPsych 销毁重建），且直接在 pointerdown 记录 RT。**不需要改动。**

当前实现已经满足标准：
- ✅ pointerdown 记 RT
- ✅ 第一次响应后 `_sartResponseMade = true` 锁定
- ✅ correctRT() 调用（虽然是冗余的，保留无害）

**需要补充的**（升级时逐步加）：
- [ ] 记录 tap_count（锁定后的重复点击次数）
- [ ] 记录 drift 指标（在 pointerdown 和 pointerup 之间追踪 pointermove）
- [ ] 记录 input_type（`e.pointerType`）
- [ ] 记录 rt_hold（pointerup - pointerdown 时间差）

**补充时的原则**：不改现有的 pointerdown 逻辑，只在旁边加记录代码。

### 类型 D：Canvas 输入的范式

**适用**：视空间（canvas 点击定位）、画钟（canvas 画笔轨迹）

Canvas 输入不是 HTML 按钮，无法用 auto-wrap 或 setupButton。需要手动在 canvas 事件中记录。

```javascript
// 视空间的 canvas 点击
var _canvasDownTime = null;
var _canvasDownX = null, _canvasDownY = null;
var _driftMax = 0, _driftPath = 0;
var _lastMoveX, _lastMoveY;

canvas.addEventListener('pointerdown', function(e) {
    _canvasDownTime = performance.now();
    _canvasDownX = e.clientX;
    _canvasDownY = e.clientY;
    _lastMoveX = e.clientX;
    _lastMoveY = e.clientY;
    _driftMax = 0;
    _driftPath = 0;
});

canvas.addEventListener('pointermove', function(e) {
    if (_canvasDownTime === null) return;
    var dx = e.clientX - _canvasDownX;
    var dy = e.clientY - _canvasDownY;
    var distSq = dx * dx + dy * dy;
    if (distSq > _driftMax * _driftMax) _driftMax = Math.sqrt(distSq);
    _driftPath += Math.hypot(e.clientX - _lastMoveX, e.clientY - _lastMoveY);
    _lastMoveX = e.clientX;
    _lastMoveY = e.clientY;
});

canvas.addEventListener('pointerup', function(e) {
    if (_canvasDownTime === null) return;
    var rt = _canvasDownTime - trialStartTime;  // RT = pointerdown 时刻
    var holdDuration = performance.now() - _canvasDownTime;
    var driftEnd = Math.hypot(e.clientX - _canvasDownX, e.clientY - _canvasDownY);
    
    // 写入数据
    trialData.rt = Math.round(rt);
    trialData.rt_hold = Math.round(holdDuration);
    trialData.drift_max = Math.round(_driftMax);
    trialData.drift_path = Math.round(_driftPath);
    trialData.drift_end = Math.round(driftEnd);
    trialData.input_type = e.pointerType;
    
    _canvasDownTime = null;
    // ... 处理响应逻辑（画点、计算距离等）
});
```

**画钟特殊**：画钟的 canvas 输入是画笔轨迹，不是离散的按钮响应。它的 pointerdown/pointermove/pointerup 已经在记录轨迹数据（stroke_id, x, y, t）。不需要改。画钟的撤销/清空/完成按钮是功能按钮，不记 RT。

### 类型 E：无响应按钮的范式

**适用**：眼动（被动观看）

不需要任何按钮相关的接入。touch-hardening.js 的全局防护（contextmenu、缩放阻止等）自动生效。

## 四、参数配置

所有参数在 `TouchHardening.CONFIG` 中，全局生效：

```javascript
CONFIG = {
    MAX_DRIFT_PX: 50,       // 漂移容忍 50px ≈ 9.5mm（覆盖老年人 95% 漂移）
    MAX_HOLD_MS: 10000,      // 按住最长 10 秒仍算有效
    DEBOUNCE_MS: 400,        // 连续点击间隔 400ms（工信部适老化规范）
    CONFIRM_FLASH_MS: 300    // 确认闪烁 300ms
};
```

**不建议各范式覆盖这些参数**，除非有明确的范式特殊需求并在代码注释中说明理由。

## 五、视觉反馈标准

### 按下反馈（pointerdown，< 60ms 响应）

```css
.elderly-pressing {
    opacity: 0.80;
    transform: scale(0.92);
    transition: opacity 0.06s, transform 0.06s;
}
```

### 确认反馈（pointerup，持续 300ms）

```css
.elderly-confirmed {
    box-shadow: 0 0 0 4px rgba(255,255,255,0.7),
                0 0 12px rgba(255,255,255,0.3);
    transition: box-shadow 0.08s;
}
```

白色边框高亮，兼容黑底（SART）和白底（其他范式）。

### 与范式自定义 CSS 的关系

**规则：范式不要写自己的 :active 缩放效果。** 由 .elderly-pressing 统一处理。

如果范式有 `:active { transform: scale(0.96) }` 之类的自定义样式，在接入标准时**删掉**，避免与 .elderly-pressing 的 scale(0.92) 叠加。

### 响应锁定后的反馈

第一次按压后按钮仍然可以按，仍然有 .elderly-pressing 和 .elderly-confirmed 视觉效果。老人不会困惑。只是数据层面不再记录新的 RT。

## 六、音效反馈（可选，默认关闭）

```javascript
// 主试决定是否开启
TouchHardening.CONFIG.SOUND_ENABLED = false;  // 默认关闭

// 按下音：1200Hz 正弦波 50ms
// 确认音：800Hz 正弦波 100ms
// 通过 Web Audio API 合成，不依赖外部文件
```

多人同时施测时避免干扰。主试可在施测前通过配置开启。

## 七、数据输出字段速查表

每个试次的 data 对象中应包含以下字段（通过 correctRT 自动添加）：

| 字段 | 类型 | 说明 | 适用范式 |
|------|------|------|---------|
| rt | number(ms) | 认知决策 RT（pointerdown 时刻） | 所有有响应的范式 |
| rt_original | number(ms) | jsPsych 原始 RT（click 时刻） | 类型 A/B |
| rt_hold | number(ms) | 按压时长 | 所有 |
| drift_max | number(px) | 最大漂移 | 所有 |
| drift_path | number(px) | 轨迹总长 | 所有 |
| drift_end | number(px) | 松手位移 | 所有 |
| tap_count | number | 点击次数（含首次） | 所有 |
| input_type | string | touch / pen / mouse | 所有 |

### 运动功能派生指标（分析时计算，不在采集时计算）

| 指标 | 公式 | 临床意义 |
|------|------|---------|
| precision_index | drift_path / rt_hold | 单位时间运动量，高=不稳 |
| tremor_ratio | drift_path / drift_max | 远>1 提示震颤（来回抖） |
| hold_variability | SD(rt_hold) across trials | 按压时长变异性 |

## 九、改动顺序（稳定优先）

```
阶段 1：升级 touch-hardening.js（一次改动，所有范式受益）
  ├── P0: html,body 加 touch-action: none
  ├── P1: pointerdown/pointermove/pointerup 中记录漂移
  ├── P1: correctRT() 扩展输出 drift + tap_count + input_type
  └── 测试：Flanker + VSTMB 的 correctRT 输出验证新字段

阶段 2：逐个范式对照检查（一个一个来，改一个测一个）
  ├── Flanker：删自定义 :active → 测试
  ├── VSTMB：删自定义 :active → 测试
  ├── N-back：补响应锁定 + tap_count → 测试
  ├── SART：补 tap_count/drift/rt_hold → 测试
  ├── 人际距离：trackRT=true + correctRT → 测试
  ├── 语音：setupButton → 测试
  └── 视空间：canvas pointerdown → 测试

阶段 3：样式统一（最后做，功能稳定后）
  ├── 按钮形状统一（圆角矩形）
  ├── 按钮尺寸统一（240×120px）
  └── 按钮颜色统一（中灰 #A0A0A0）
```

## 十、不改的东西（稳定红线）

- **不改 SART 的 pointerdown 手动记录逻辑** — 它能用，不动
- **不改 jsPsych auto-wrap 的核心流程** — 只在上面加字段
- **不改 CONFIG 的默认值** — 50px 漂移、400ms 防抖、300ms 闪烁都有文献依据
- **不改画钟的画笔轨迹记录** — 它不是按钮响应
- **不改鼠标路径** — 开发调试必须不受影响
