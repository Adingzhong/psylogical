# 注意力探针（Attention Probe）统一标准

> 日期：2026-04-09
> 用途：所有范式统一加入注意力自评探针，用于监测被试在整个电池中的注意力波动

---

## 一、为什么每个范式都要加

1. **注意力波动本身就是 MCI 的指标**——健康老人注意力随任务推进缓慢下降，MCI 患者下降更快更不稳定
2. **可以识别无效数据段**——如果某个 block 的自评只有 2/9，说明那段数据可能需要剔除
3. **跨范式疲劳曲线**——10个范式做下来约1小时，注意力评分可以画出整体疲劳趋势，为范式排序优化提供依据
4. **几乎零成本**——每次评分只要5秒，被试感受是"休息一下"，不增加认知负担

---

## 二、探针内容标准

### 量表

**9点 Likert 量表**（Robertson et al., 1997; Seli et al., 2016）

### 指导语

```
请评价您刚才对任务的专注程度
```

### 锚点

```
1 = 完全走神    9 = 非常专注
```

> 注意：用"走神"而不是"不专注"——对老年人来说"走神"更口语化更好理解

### 数据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `subject_id` | string | 被试ID |
| `paradigm` | string | 范式名 |
| `probe_position` | string | 探针位置（如 `after_block_1`、`end`） |
| `attention_rating` | int 1-9 | 自评分数 |
| `probe_rt_ms` | int | 从探针呈现到选择的反应时（ms） |
| `probe_timestamp` | string | ISO 8601 时间戳 |

## 四、每个范式的插入位置

### 规则

- **有多 block 的范式**：每个 block 结束后插入一次 + 最后一个 block 结束后也插入一次
- **单 block / 短范式**：仅在范式结束后（最后一个试次之后、数据保存之前）插入一次
- **TMT 特殊**：6个子任务太碎，不是每个之间都加，每 2 个子任务后加一次（共 3 次）

### 具体方案

| 范式 | 总时长约 | 探针次数 | 插入位置 | probe_position 值 |
|------|---------|---------|---------|-------------------|
| **Flanker** | ~5min (正式2.8min, 48试次) | 1 | Block 1→2 之间的休息屏 | `after_block_1` |
| **SART** | ~4min (正式1.5min, 36试次) | 1 | 全部36试次后 | `end` |
| **N-back** | ~6min (正式3.9min, B1+B2+B3) | 2 | B1 后 + B3 后 | `after_B1`, `after_B3` |
| **VSTMB** | ~8min (正式5.8min, 3×18试次) | 3 | 每个条件正式试次后 | `after_object`, `after_color`, `after_binding` |
| **TMT** | ~8min (6子任务, 各30-90s) | 1 | 全部子任务结束后 | `end` |
| **Clock** | ~5min (命令+临摹, 自定步速) | 1 | 临摹结束后 | `end` |
| **Interpersonal** | ~3min (正式1.4min, 8试次) | 1 | 正式试次结束后 | `end` |
| **Visuospatial** | ~10min (正式5.9min, 16试次) | 2 | 练习结束后 + 正式结束后 | `after_practice`, `end` |
| **Eyetracking** | ~7min (正式4.3min, 40张图) | 1 | Block 1→2 之间的休息屏 | `after_block_1` |
| **Speech** | ~11min (11项录音, 自定步速) | 2 | VFT结束后 + 全部结束后 | `after_vft`, `end` |

**总计**：整个电池 15 次探针，每次 5 秒 ≈ 额外 1.2 分钟

### 设计原则

- **短范式（≤3min）只在结尾加1次**——不打断节奏
- **长范式在自然休息点加**——被试感觉是"休息顺便评个分"
- **TMT 虽然有6个子任务但每个很短**——中间不加，只在全部结束后加1次
- **没有硬性文献标准规定频率**——关键是不能让探针比任务本身还烦人

## 六、数据保存

注意力探针数据有两种保存方式（二选一或都用）：

### 方式A：嵌入范式 CSV（推荐）

在每个范式的 trial CSV 里加一行 `trial_type: 'attention_probe'`，字段用空值填充不适用的列。好处是数据和范式在一起，分析时不用合并文件。

### 方式B：独立 CSV

每个范式额外输出一个 `{paradigm}_{sid}_{ts}_probes.csv`。好处是字段干净，坏处是多了文件。

### 跨范式汇总

电池结束后，启动器从 localStorage 或服务器收集所有范式的 probe 数据，生成：
```
attention_probes_{sid}_{ts}.csv
```
包含整个电池的注意力波动曲线数据，可直接画图分析。
