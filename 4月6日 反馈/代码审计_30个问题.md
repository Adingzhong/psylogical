# Web Battery 代码审计 — 30个问题清单

> 审计日期：2026-04-09
> 审计范围：`web-battery/` 全部10个范式 + 启动器 + 公共模块
> 审计方法：4个并行Agent深度读码（数据保存、视觉一致性、启动器流程、CSV格式）
> 排序原则：P0 = 会丢数据，P1 = 可能丢数据，P2 = 数据质量，P3 = 视觉体验

---

## P0 — 会丢数据（必须修）

---

### #1 saveData() 没有 await，用户点返回就丢数据

**一句话**：Flanker、SART、Speech 三个范式在实验结束时，保存数据的函数还没跑完就弹出了"已完成"页面，老人一点"返回"按钮，浏览器关掉窗口，数据就没了。

**详细参数**：
- **Flanker** `flanker.js:490-492`
  ```js
  on_finish: function () {
    saveData();           // async函数，没有await！
    showEndScreen(...);   // 立刻弹出完成页
  }
  ```
- **SART** `sart.js:407-412` — 同样的问题
- **Speech** `speech.js:534-537` — 同样的问题（虽然timeline里有一个await版本，但on_finish又调了一次非await版本）

**修复方向**：`on_finish` 改为 async，await saveData() 之后再调 showEndScreen()。或者把 saveData 移到 timeline 的 call-function trial 里（像 N-back、VSTMB 那样）。

---

### #2 N-back 的 checkpoint 在数据保存完成前就被清掉了

**一句话**：N-back 调用保存函数后没等它完成就把 checkpoint（断点备份）清掉了。如果保存失败，checkpoint 也没了，数据彻底丢失。

**详细参数**：
- `nback.js:1296-1303`
  ```js
  trySaveData(csvFn, csvData, jsonFn, jsonData);  // 没有 await！
  LocalPack.add(csvFn, csvData);
  LocalPack.add(jsonFn, jsonData);
  checkpoint.clear();  // 立刻清除！此时 trySaveData 的 fetch 可能还在飞
  ```

**修复方向**：`await trySaveData(...)`，然后再 `checkpoint.clear()`。

---

### #3 除眼动外，所有范式的网络请求都没有超时

**一句话**：如果现场WiFi信号不好，fetch 请求会无限挂起，永远不触发 catch 回退（本地下载），用户关页面数据就没了。

**详细参数**：
- 只有 **Eyetracking** (`eyetracking.js:894`) 加了 `AbortController` + 15s 超时
- 其余 **9个范式** 的 fetch 都没有 timeout，包括：
  - `flanker.js:449` / `sart.js:379` / `nback.js:276` / `vstmb.js:981`
  - `tmt.js` (通过 data-sync.js) / `clock.js:544` / `interpersonal.js:423`
  - `visuospatial.js:1006` / `speech.js:334`

**修复方向**：给所有 fetch 加 `AbortController`，15-30s 超时后触发 fallback 下载。可以写一个公共 `safeFetch()` 函数。

---

### #4 启动器的 runAll() 范式崩溃时无限等待

**一句话**：如果某个范式窗口崩溃了或者被手动关掉了，启动器会永远卡在那个范式，整个测试电池停摆，后面的范式都跑不了。

**详细参数**：
- `index.html:356-360`
  ```js
  await new Promise(r => {
    const iv = setInterval(() => {
      if (localStorage.getItem(`done_${sid}_${p.id}`)) { clearInterval(iv); r(); }
    }, 1000);   // 每1秒轮询一次，永不超时
  });
  ```
- 没有存 `window.open()` 返回的窗口引用，无法检测窗口是否已关闭
- 没有超时机制，没有"跳过"按钮

**修复方向**：保存 window 引用，轮询 `win.closed` 属性；加超时（如5分钟）；加跳过按钮。

---

### #5 多文件保存只检查第一个 fetch 的状态

**一句话**：Flanker、SART、VSTMB 保存CSV和JSON两个文件，但只检查第一个是否成功，第二个失败了不知道，导致服务器上数据不完整且没有触发本地下载备份。

**详细参数**：
- **Flanker** `flanker.js:449-464`
  ```js
  const resp = await fetch(...);       // 保存 trial CSV
  if (!resp.ok) throw new Error();     // ✓ 检查了
  await fetch(...);                     // 保存 rating CSV
  // ✗ 没有检查 resp.ok！
  ```
- **SART** `sart.js:379-393` — 同样：第一个 fetch 检查了，第二个没有
- **VSTMB** `vstmb.js:981-1002` — JSON summary 的 fetch 没有状态检查

**修复方向**：每个 fetch 都检查 `resp.ok`，任何一个失败都触发 fallback。

---

### #6 眼动范式部分数据保存没有降级方案

**一句话**：Eyetracking 的 trial CSV 和 summary JSON 保存到服务器时，如果服务器挂了，没有 fallback 下载，数据静默丢失。

**详细参数**：
- `eyetracking.js:895`
  ```js
  await fetch(`${API_BASE}/api/save`, { ... });
  // 没有 .catch(() => downloadBlob(...))
  ```
- `eyetracking.js:909` — summary JSON 同样没有 fallback
- 对比：Eyetracking 的视频和 timestamps CSV **有** fallback（downloadBlob），但行为数据没有

**修复方向**：给 trial CSV 和 summary JSON 的 fetch 加 try/catch + downloadBlob fallback。

## P1 — 可能丢数据（尽快修）

---

### #7 8个范式没有防止重复保存

**一句话**：如果 jsPsych 的 on_finish 意外触发两次，8个范式会向服务器发两份数据。不会丢但会产生混淆的重复文件。

**详细参数**：
- **有 `_dataSaved` 标志的**：Flanker (`flanker.js:429`)、Speech (`speech.js:319`)
- **没有防护的**：SART、N-back、VSTMB、Clock、Interpersonal、Eyetracking、TMT、Visuospatial

**修复方向**：所有范式的 saveData() 开头加 `if (_saved) return; _saved = true;`。

---

### #8 没有被试ID时静默使用假ID

**一句话**：如果启动器传参失败（URL里没有 `?sid=`），范式会静默使用 "P001" 或 "TEST_xxxx" 作为被试ID，数据存到错误目录，和真实被试对不上。

**详细参数**：
- 默认 `'P001'`：Clock (`clock.js:407`)、Visuospatial (`visuospatial.js:755`)、Eyetracking (`eyetracking.js:408`)
- 默认 `'TEST_' + Date.now()`：Flanker (`flanker.js:477`)、Speech (`speech.js:79`)
- 默认 `'TEST'`：N-back (`nback.js:23`)

**修复方向**：范式启动时检查 sid 参数，如果为空弹出警告页面而不是静默继续。

---

### #9 启动器不检测范式窗口是否真的打开了

**一句话**：如果浏览器弹窗拦截器阻止了 window.open()，启动器不知道，会一直等那个从未打开的范式完成。

**详细参数**：
- `index.html:286`
  ```js
  window.open(`${p.path}?sid=${encodeURIComponent(sid)}`, '_blank');
  // 返回值没有保存！无法检测 null（被拦截）
  ```
- 没有 `if (!win) alert('弹窗被拦截')` 逻辑

**修复方向**：保存 window.open 返回值，检查是否为 null，提示用户允许弹窗。

---

### #10 SART 的摄像头 stopAndSave() 没有 await

**一句话**：SART 结束时摄像头停止录制的函数没等它完成，如果页面提前关闭，视频的最后几个 chunk 来不及合并导出。

**详细参数**：
- 需要确认 `sart.js` 的 camera stop 调用是否在 await 链中
- 对比 Flanker (`flanker.js:983-988`)、VSTMB (`vstmb.js:731`) 都正确 await 了 `ParadigmCamera.stopAndSave()`

**修复方向**：确保 `await ParadigmCamera.stopAndSave()` 在 saveData 之后、showEndScreen 之前完成。

---

### #11 启动器没有 checkpoint 恢复机制

**一句话**：如果浏览器崩溃了，localStorage 里有断点数据、OPFS 里有视频 chunk，但重启后启动器不会检测和恢复这些数据，对用户完全不可见。

**详细参数**：
- `paradigm-camera.js` 有 `detectOrphaned()` 和 `recoverSession()` 函数（已实现）
- 但 `index.html` **从未调用**这两个函数
- localStorage 里的 checkpoint 键（`checkpoint_{paradigm}_{sid}`）也没有被检测

**修复方向**：启动器加载时调用 `ParadigmCamera.detectOrphaned()`，检测 localStorage 里的 checkpoint，显示恢复提示。

---

### #12 ZIP 下载可能被浏览器静默拦截

**一句话**：实验结束时自动下载 ZIP 文件用的是 `a.click()`，如果浏览器拦截了下载，没有任何提示，用户以为数据已保存但实际 ZIP 没下载成功。

**详细参数**：
- `end-screen.js:84` — `a.click()` 触发下载
- 没有检查下载是否成功
- 如果 JSZip 库未加载（`typeof JSZip === 'undefined'`），ZIP 生成直接跳过，也没有提示

**修复方向**：下载后显示提示；如果 JSZip 不可用，触发单文件逐个 downloadBlob。

---

## P2 — 数据质量问题（影响分析）

---

### #13 6个范式的 CSV 没有正确转义

**一句话**：如果数据值里包含逗号或引号，CSV 结构会损坏，Excel 打开后列错位。

**详细参数**：
- **没有 RFC 4180 转义的**：
  - Flanker `flanker.js:~395` — `String(v)` 直接拼接
  - SART `sart.js:~335` — 同上
  - VSTMB `vstmb.js:~generateCSV` — 同上
  - Clock `clock.js:~trajectoryCSV` — 同上
  - Interpersonal `interpersonal.js:~390` — 同上
  - Eyetracking `eyetracking.js:~370` — `Object.values(t).join(',')` 无转义
- **有正确转义的**：N-back、TMT、Visuospatial、Speech
  - 正确做法：`if (s.includes(',') || s.includes('"')) return '"' + s.replace(/"/g, '""') + '"';`

**修复方向**：写一个公共 `escapeCSV(value)` 函数，所有范式统一调用。

---

### #14 RT（反应时）字段名混乱，7种不同命名

**一句话**：10个范式用了7种不同的字段名记录反应时间，有的用秒有的用毫秒，后续数据分析需要为每个范式单独写解析代码。

**详细参数**：
| 字段名 | 单位 | 范式 |
|--------|------|------|
| `reaction_time` | 秒？毫秒？不明 | Flanker, VSTMB |
| `reaction_time_ms` | ms（1位小数） | SART |
| `rt_ms` | ms（整数） | Flanker, SART, N-back |
| `rt` | 秒（3位小数） | Interpersonal |
| `clickRTms` | ms（整数） | Visuospatial |
| `duration_ms` | ms | Eyetracking, Speech |
| `completion_time_s` | 秒 | TMT |

- Flanker 和 SART 还**同时输出两个** RT 字段（冗余且单位不同）

**修复方向**：统一使用 `rt_ms`（整数毫秒）。保留冗余字段但命名清晰（如 `rt_sec` 和 `rt_ms`）。

---

### #15 触摸 RT 校正只有4个范式做了

**一句话**：touch-hardening.js 的 correctRT() 会把 RT 从"手指松开"时刻修正为"手指按下"时刻（认知决策时间），但只有4个范式调了，其余范式的 RT 包含了老人按住时间，跨范式不可比。

**详细参数**：
- **调了 `TouchHardening.correctRT(data)` 的**：
  - Flanker `flanker.js:708`
  - SART `sart.js:502`
  - N-back `nback.js:459,762,972`
  - VSTMB `vstmb.js:855`
- **没调的**：Clock、Interpersonal、Eyetracking、Speech、TMT、Visuospatial
- **其中有影响的**：Interpersonal（有触摸响应的 RT，但没校正）

**修复方向**：Interpersonal 加上 correctRT()。其余范式无触摸 RT 响应，不需要。

---

### #16 文件名前缀大小写和命名不统一

**一句话**：10个范式保存文件时用了不同的大小写和缩写，批处理脚本无法用统一规则匹配。

**详细参数**：
| 范式 | 文件前缀 | 问题 |
|------|---------|------|
| Flanker | `Flanker_` | 首字母大写 |
| SART | `SART_` | 全大写 |
| N-back | `Nback_` | 首字母大写 |
| VSTMB | `VSTMB_` | 全大写 |
| TMT | `TMT_` | 全大写 |
| Clock | `clock_` (checkpoint) | 全小写 |
| Interpersonal | **`IPD_`** | ⚠️ 缩写，和 paradigm 名 "interpersonal" 不匹配 |
| Speech | `Speech_` | 首字母大写 |
| Eyetracking | `eyetracking_` | 全小写 |
| Visuospatial | **`visuospatial_navigation_`** | ⚠️ 多了 "navigation" |

**修复方向**：统一为全小写 `{paradigm}_{sid}_{timestamp}` 格式。IPD→interpersonal，visuospatial_navigation→visuospatial。

---

### #17 时间戳格式混乱

**一句话**：不同范式用了不同的时间戳格式，跨范式做时间对齐非常困难。

**详细参数**：
| 格式 | 范式 |
|------|------|
| ISO 8601（完整日期时间） | SART, TMT, Speech |
| `HH:mm:ss`（无日期） | Interpersonal |
| 秒偏移量（从任务开始算） | Clock, Eyetracking |
| **完全没有** | N-back, Visuospatial |

**修复方向**：所有范式加 ISO 8601 时间戳字段。相对时间可以保留但额外加绝对时间。

---

### #18 只有4个范式输出 JSON Summary

**一句话**：6个范式只有 CSV 没有 JSON 摘要，提取关键指标（正确率、平均RT等）需要逐行解析 CSV。

**详细参数**：
- **有 JSON Summary 的**：SART（SDT指标 d'/A'/β）、N-back（block 摘要）、VSTMB（SDT指标）、Eyetracking（实验参数）
- **只有 CSV 的**：Flanker、TMT、Clock、Interpersonal、Speech、Visuospatial

**修复方向**：为缺少 JSON 的范式补上 summary JSON，至少包含：总试次数、正确率、平均RT、关键指标。

## P3 — 视觉一致性（影响被试体验）

---

### #19 "继续"按钮 — 6种不同的渲染方式

**一句话**：被试在每个范式都要反复点"继续"，但这个按钮在不同范式里长得不一样——SART 有蓝色阴影，其他的没有；margin、字号各不相同。

**详细参数**：
| 写法 | 范式 | 视觉差异 |
|------|------|---------|
| `class="jspsych-btn btn-primary"` | Eyetracking, Clock | 蓝色实心（common.css） |
| `class="jspsych-btn" style="margin-top:24px"` | VSTMB, N-back | 蓝色，各种 margin |
| `class="jspsych-btn instr-continue-btn"` | Flanker, Speech | 蓝色 + 自定义 margin 类 |
| `class="jspsych-btn" style="margin:20px auto;min-height:96px"` | Interpersonal | 蓝色 + 又一种 margin |
| `class="sart-instr-btn"` | SART | **完全独立样式**，有 `box-shadow: 0 4px 16px rgba(21,101,192,0.3)` |
| Canvas 绘制 | TMT, Visuospatial | 像素级自绘，完全不同 |

**修复方向**：统一用 `class="jspsych-btn btn-primary"` 或定义 `.instr-continue-btn` 在 common.css 里，删除 SART 的独立按钮样式。

---

### #20 指导语页面 — 3套独立 CSS 容器

**一句话**：指导语页面在不同范式里用了不同的 CSS 类名，背景、标题字号、行间距都不同，被试从一个范式切到另一个会感觉"换了个APP"。

**详细参数**：
| 容器类名 | 标题字号 | 正文行高 | 背景 | 范式 |
|---------|---------|---------|------|------|
| `.instruction-page`（common.css） | 52px | 1.7 | 白色 | VSTMB, Clock, Eyetracking, Interpersonal |
| `.instr-page`（自定义） | 48px | 1.6 | 白色 | Flanker, Speech |
| `.sart-instr-page`（自定义） | 52px | 1.8 | **渐变灰白** | SART |
| `.nback-instr-rich`（自定义） | **36px** | 未指定 | 白色 | N-back |

- Flanker/Speech 的 `.instr-page` 和 common.css 的 `.instruction-page` 差一个横线，完全没复用

**修复方向**：全部统一到 `.instruction-page`（common.css），删除 `.instr-page`、`.sart-instr-page`、`.nback-instr-rich`。

---

### #21 响应按钮颜色不统一

**一句话**：试次中的响应按钮在不同范式里用了不同的灰色——有的深灰、有的浅灰、有的白色，被试会觉得按钮"变了"。

**详细参数**：
| 范式 | 按钮类 | 底色 | 边框 | 按下色 |
|------|--------|------|------|--------|
| Flanker | `.response-btn` | `#BFBFBF` | `#4D4D4D` 2px | `#8C8C8C` |
| VSTMB | `.vstmb-btn` | `#BFBFBF` | `#4D4D4D` 2px | `#8C8C8C` |
| N-back | `.nback-btn-3` | `#F0F0F0` | `var(--border)` 3px | `#D0D0D0` |
| SART | `.sart-tap-btn` | `#FFFFFF` | 无 | `#999999` |
| Interpersonal | `.stop-btn` | `#E0E0E0` | `#999` 4px | `#999` |

- Flanker 和 VSTMB 颜色一样但**各自独立定义了一份代码**

**修复方向**：在 common.css 定义统一的 `.response-btn` 样式，所有范式引用。科学上需要中性灰（避免 Stroop 干扰），统一用 `#BFBFBF`。

---

### #22 注视点（Fixation Cross）规格不统一

**一句话**：注视点的大小和颜色在不同范式之间差异很大——Flanker 是大白色的，Interpersonal 和 Eyetracking 是小黑色的。

**详细参数**：
| 范式 | 大小 | 颜色 | 背景 | 文件位置 |
|------|------|------|------|---------|
| Flanker | `9.4vh`（约90px） | 白色 `#FFFFFF` | 黑 | `flanker.html:14` |
| Interpersonal | `80px` | 黑色 `var(--text)` | 白 | `interpersonal.html:51` |
| Eyetracking | `80px` | 黑色 `#000000` | 灰 `#808080` | `eyetracking.html:48` |
| SART | 未明确定义 | — | 黑 | — |
| 其余 | 无注视点 | — | — | — |

**修复方向**：统一为 `80px`，颜色根据背景自动反转（黑底用白色，白/灰底用黑色）。在 common.css 定义 `.fixation`。

### #23 注意力评分（Rating 1-9）两套样式

**一句话**：Flanker 和 SART 都有 block 间注意力评分，但按钮大小、底色、选中色、阴影全部不同。同一个量表两种外观。

**详细参数**：

| 字号 | 36px | 40px |
| 文件位置 | `flanker.html:234-252` | `sart.html:270-290` |

**修复方向**：在 common.css 定义 `.rating-btn`，两个范式统一引用。

### #24 错误反馈样式各异

**一句话**：练习阶段答错时，不同范式给的视觉反馈完全不同——Flanker 是红色大X，SART 是红色文字，N-back 是绿/红大字。

**详细参数**：
| 范式 | 反馈形式 | 字号 | 颜色 | 持续时间 | 文件位置 |
|------|---------|------|------|---------|---------|
| Flanker | 红X + 白色"正确答案:..." | 72px + 44px | `#F44336` + `#FFFFFF` | 1500ms | `flanker.html:52-70` |
| SART | 红色文字 "X 数字3别按!" | 56px | `#FF5555` | 800ms | `sart.html:73-82` |
| N-back | 绿/红大字 "✓ 正确" / "✗ 错误" | 56px | `#4CAF50` / `#F44336` | 1000ms | `nback.html:126-145` |
| VSTMB | 类似 N-back | 56px | 绿/红 | — | `vstmb.html:86-100` |
| 其余 | 无错误反馈 | — | — | — | — |

### #26 触摸反馈时序冲突

**一句话**：touch-hardening.js 给按钮加了 0.06s 的按下动画，但 SART、VSTMB、N-back、Flanker 各自定义了"无动画"的 `:active` 样式，两套同时生效导致按下反馈时快时慢。

- `nback.html:67-70` — `.nback-btn-3:active { /* 无 transition */ }`
- `flanker.html:218-221` — `.response-btn:active { /* 无 transition */ }`

**修复方向**：删除各范式自定义的 `:active` 样式，统一由 touch-hardening.js 的 `.elderly-pressing` / `.elderly-confirmed` 控制。

### #28 z-index 层级冲突

**一句话**：多个范式用了 position:fixed 的浮层，z-index 互相打架，可能出现按钮被指导语遮住或者指导语上的按钮可以点击的问题。

**详细参数**：
- **SART**：`.sart-instr-page { z-index: 60 }` < `#jspsych-html-button-response-btngroup { z-index: 70 }` → 指导语显示时按钮可能穿透可点击
  - `sart.html:95,100`
- **VSTMB**：instruction btngroup z:200 vs probe btngroup z:100，不同页面按钮层级不同
  - `vstmb.html:382-401`
- **TMT**：canvas 没有 z-index，instruction overlay z:100，可能不能可靠覆盖
  - `tmt.html:22,58`

**修复方向**：定义统一的 z-index 分层规范（如 overlay:1000, buttons:500, content:1），各范式统一遵守。

### #29 白↔黑转场无过渡动画

**一句话**：Flanker 和 SART 在指导语（白底）到试次（黑底）之间是硬切换，没有渐变过渡，对老年人视觉刺激较大，可能引起不适。

**详细参数**：
- **Flanker** `flanker.js:484` — `document.body.style.background = on ? '#000' : '#FFF'`（硬切）
- **SART** — 全局黑底，指导语用 fixed overlay 白底覆盖，移除 overlay 时硬切回黑底
- **Eyetracking** — 白底指导语 → 灰底试次，也是硬切
- 所有范式都没有 CSS transition 做背景色渐变

**修复方向**：加 `transition: background 0.3s ease` 或用 opacity fade overlay 做 300ms 过渡。

### #30 shared-config.js 和 common.css 主色冲突

**一句话**：CSS 变量定义的主色（`#1565C0`）和 JS 配置定义的主色（`#1A8CFF`）是两种不同的蓝色，如果有范式同时引用两个来源会出现色差。

**详细参数**：
- `common.css:4` — `--primary: #1565C0`（深蓝）
- `shared-config.js:10` — `primary: '#1A8CFF'`（亮蓝）
- 目前只有 TMT 和 Visuospatial 导入了 shared-config.js（用 ES Module），其余用 common.css
- 多个范式直接硬编码 `#1565C0`（如 N-back `nback.html:173,211`、SART `sart.html:129`）

**修复方向**：统一为一个颜色值（推荐 `#1565C0`，和 common.css 一致），删除 shared-config.js 中的冗余定义，硬编码全部改为 `var(--primary)`。

## 附：跨范式问题汇总

### Checkpoint（断点保存）复制粘贴了10遍
每个范式内联了一份 ~40-80 行的 checkpoint 逻辑，实现方式有5种变体（对象字面量 / IIFE / 工厂函数 / 全局变量 / 压缩一行）。改一处要改10个文件。

### `shared-config.js` 形同虚设
设计为 ES Module，但只有 TMT 和 Visuospatial 导入了它。其余8个范式用 `<script>` 标签加载，无法 import。

### `common.css` 被大量 inline style 覆盖
所有10个范式都链接了 common.css，但每个范式都用 `<style>` 块重新定义了按钮、指导语、注视点等样式，等于公共样式白写了。

### 启动器 message listener 泄漏
`index.html:287-294` — 范式完成后通过 postMessage 通知启动器，但如果范式崩溃，listener 不会被清理，反复启动范式会累积 listener。

### 服务端没有 session 概念
`server/main.py` 只按 `{subject_id}/{paradigm}/` 存文件，没有 session 时间戳、没有 manifest、没有原子操作。无法区分同一被试的多次测试。
